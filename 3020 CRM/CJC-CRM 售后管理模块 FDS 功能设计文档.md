## 1\. 文档概述

### 1.2 适用范围

## 2\. 整体业务概述

### 2.1 系统定位

CRM售后管理模块服务于制造业企业的设备全生命周期售后服务，涵盖从潜在客户培育、设备出货后的现场安装调试、到设备故障后的维修质量管控全流程。模块与 MDM（主数据管理）深度集成，共享客户档案等基础数据。

### 2.2 业务整体流程

```
[客户档案 MDM]
     │
     ├──► [预测客户] ──拜访记录──► 客户成功 ──► [正式客户档案]
     │
     ├──► [售后回访] ──沟通记录──► 已关闭
     │
     └──► [设备全生命周期服务]
              │
              ├── [现场任务] ──设备清单+任务明细──► 派工 ──服务中──► 关闭
              │
              ├── [整机调试] ──调试任务+点检明细──► 派工 ──调试中──► 点检完成──► 关闭
              │
              └── [设备维修] ──维修记录+投诉/建议──► 派工 ──维修中──► 
                      ├── [有投诉/建议] ──► 待质检处理 ──► 质检完成 ──► 销售确认 ──► 关闭
                      └── [无投诉/建议] ──► 销售确认 ──► 关闭
```

### 2.3 模块整体架构

| 业务域 | 主实体 | 单据状态数 | 审批状态 | 备注  |
| --- | --- | --- | --- | --- |
| 客户培育 | 预测客户 PredictCustomer | 4   | 无   | 含拜访子表 |
| 售后回访 | 客户售后回访 CustomerReturnVisit | 3   | 无   | 含沟通记录子表 |
| 项目进度 | 项目进度 ProjectProgress | 2   | 无   | 含外采/自制两套明细 |
| 现场服务 | 现场任务 FieldService | 4   | 有   | 含设备清单+任务明细子表 |
| 整机调试 | 整机调试服务 MachineDebugService | 5   | 有   | 含调试任务+点检子表 |
| 设备维修 | 设备维修服务 EquipmentRepairService | 7   | 有   | 含维修记录+投诉/建议子表 |

### 2.4 设计边界

- 客户档案来源于 MDM，不在本模块维护
- 「客户成功」线下审批在系统外完成，审批通过后业务经理在系统内操作
- 设备点检标准项目由系统预置，不开放用户自定义
- 签字图片以 Base64 存储，访问权限受控

## 3\. 全局通用设计

### 3.1 编码规则

| 单据  | 编码格式 | 示例  | 序号规则 |
| --- | --- | --- | --- |
| 预测客户 | YC-YYYYMMDD-序号 | YC-20260605-001 | 当日3位顺序码（001-999），按日独立递增，每日零点重置 |
| 客户售后回访 | HF-YYYYMMDD-序号 | HF-20260605-001 | 同上  |
| 项目进度 | PJ-YYYYMMDD-序号 | PJ-20260605-001 | 同上  |
| 现场任务 | SC-YYYYMMDD-序号 | SC-20260605-001 | 同上  |
| 整机调试服务 | ZJTS-YYYYMMDD-序号 | ZJTS-20260605-001 | 同上  |
| 设备维修服务 | WX-YYYYMMDD-序号 | WX-20260605-001 | 同上  |

### 3.2 通用状态定义

#### 3.2.1 单据状态（业务流向）

| 状态值 | 适用单据 | 含义  |
| --- | --- | --- |
| 开立  | 预测客户/售后回访/项目进度 | 初始状态，可编辑 |
| 已生效 | 预测客户 | 批量生效后，可转成功或失效 |
| 已成功 | 预测客户 | 终态，客户转正完成，不可编辑 |
| 已失效 | 预测客户 | 终态，可重新开立 |
| 已提交 | 售后回访 | 回访完成，等待关闭 |
| 已关闭 | 售后回访/项目进度/现场任务/整机调试/设备维修 | 终态，不可逆 |
| 草稿  | 现场任务/整机调试/设备维修 | 初始状态，未提交审批 |
| 已派工 | 现场任务/整机调试/设备维修 | 审批通过后，已指派服务人员 |
| 服务中 | 现场任务 | 服务人员已到场开始作业 |
| 调试中 | 整机调试 | 现场调试进行中 |
| 点检完成 | 整机调试 | 所有点检项目通过 |
| 维修中 | 设备维修 | 维修人员正在作业 |
| 待质检处理 | 设备维修 | 客户提出投诉/建议，需质检员介入 |
| 质检完成 | 设备维修 | 质检员已完成处理 |
| 销售确认 | 设备维修 | 销售部门已确认 |

#### 3.2.2 审批状态（控制能否派工）

> 以下审批状态字段不在各单据模型中维护，由平台审批基础设施统一管理。

| 状态值 | 含义  |
| --- | --- |
| 保存  | 初始状态，未提交审批 |
| 待审核 | 审批流进行中 |
| 审批通过 | 可进入派工环节 |
| 审批不通过 | 打回，申请人修改后可重新提交 |
| 已收回 | 申请人主动撤回 |
| 已失效 | 审批超时或被作废 |

### 3.3 通用校验规则

| 规则  | 表达式 | 适用单据 |
| --- | --- | --- |
| 预测客户转正规则 | `status == 'EFFECTIVE'` | 仅已生效才允许「客户成功」 |
| 预测客户删除规则 | `status == 'OPEN'` | 仅开立状态允许删除 |
| 现场任务派工规则 | `approvalStatus == 'APPROVED' && status == 'DRAFT'` | 仅审批通过才允许派工 |
| 现场任务关闭规则 | `status == 'IN_SERVICE'` | 服务中状态才允许关闭 |
| 整机调试派工规则 | `approvalStatus == 'APPROVED' && status == 'DRAFT'` | 仅审批通过才允许派工 |
| 整机调试关闭规则 | `status == 'INSPECTION_DONE'` | 点检完成后才允许关闭 |
| 设备维修派工规则 | `approvalStatus == 'APPROVED' && status == 'DRAFT'` | 仅审批通过才允许派工 |
| 设备维修关闭规则 | `status == 'SALES_CONFIRMED' \| (complaint == null && suggestion == null)` | 销售确认后或无投诉/建议时可直接关闭 |
| 售后回访提交规则 | `status == 'OPEN'` | 开立状态才允许提交 |
| 项目进度关闭规则 | `status == 'OPEN'` | 开立状态允许关闭 |

### 3.4 数据权限规则

| 角色  | 数据可见范围 |
| --- | --- |
| 业务经理（本人） | 创建人=当前登录人的记录 |
| 售后服务人员 | 服务人员=当前登录人的记录 |
| 售后主管 | 本部门全部数据（可编辑） |
| 销售主管 | 全部数据（只读） |
| 管理员 | 全部数据（可编辑） |

### 3.5 脱敏规则

- **联系方式**字段：存入全号，展示时调用脱敏接口（手机号隐藏中间4位，如 138\*\*\*\*5678）
- **签字图片**：仅服务创建人和当前登录人可见；Base64 格式存储

### 3.6 公共组件说明

- **左树快捷查询**：主子表结构单据（预测客户、售后回访、现场任务、整机调试、设备维修）支持左树切换快速定位
- **全部/列表/与我相关**：主子表单据的视图切换
- **导出 + 默认方案**：电脑端非弹出框页面表格标配
- **扫码功能**：手机端/平板端进入页面保持扫码状态
- **状态页签**：手机端/平板端状态查询页签平铺且全部在最后

## 4\. 各模块详细功能设计

### 4.1 预测客户（模块编码：CRM-AF-PREDICT）

#### 4.1.1 模块概述

业务经理在「预测客户信息维护」中新增、编辑自己所负责的潜在预测客户，记录从开拓、多次拜访、转正到失效的完整生命周期数据。

#### 4.1.2 关联本体

- 主实体：PredictCustomer（预测客户）
- 子表：PredictCustomerVisit（预测客户拜访记录，1:N）
- 引用：BD_Customer（客户档案，来自MDM，仅通过客户名称关联）

#### 4.1.3 功能场景

**场景一：业务经理新增预测客户**  
业务经理开拓新客户，在列表页点击【新建】，填写客户名称、地址、企业规模、生产线开机率等主表字段，保存后自动生成编码 YC-YYYYMMDD-序号。

**场景二：多次拜访积累**  
客户经多次拜访，业务经理在拜访子表中持续补充每次的拜访目的、日期、沟通记录。

**场景三：批量生效**  
业务经理勾选多条「开立」状态记录，点击【批量生效】，状态批量变更为「已生效」。

**场景四：客户成功（转正）**  
线下审批完成后，业务经理点击【客户成功】，状态变更为「已成功」，记录 `转化时间`，此后记录锁定不可编辑。

**场景五：批量失效**  
业务经理勾选多条「已生效」记录，点击【批量失效】，状态批量变更为「已失效」。

**场景六：重新开立**  
业务经理对「已失效」记录点击【重新开立】，状态恢复为「开立」，可重新编辑。

#### 4.1.4 页面结构

- **列表页**：表格展示，左树按「全部/我的预测客户」分组，支持「开立/已生效/已成功/已失效」状态筛选
- **新增/编辑页**：主表表单 + 拜访记录子表（Tab页签）
- **字段展示规则**：
    - 序号：自动生成 `YC-YYYYMMDD-XXX`，不可编辑
    - 业务经理：默认当前登录人，不可修改
    - 状态：由系统根据操作自动变更，不允许手动选择
    - 企业规模/运营情况/生产线开机率/客户评级：下拉选择枚举值
    - 联系方式：脱敏展示，编辑时明文

#### 4.1.5 操作流程

```
列表页
  │
  ├──[新建]──► 编辑页（主表+拜访子表）──[保存]──► 列表页（开立状态）
  │
  ├──[批量生效]──► 选中记录状态──► 已生效
  │
  ├──[客户成功]──► 仅「已生效」可用 ──► 已成功（锁定）──► 记录不可编辑
  │
  ├──[批量失效]──► 仅「已生效」可用 ──► 已失效
  │
  ├──[重新开立]──► 仅「已失效」可用 ──► 开立
  │
  └──[删除]──► 仅「开立」可用 ──► 确认提示 ──► 删除
```

#### 4.1.6 数据校验规则

- 客户名称：必填，最大200字符
- 客户联系方式：脱敏存储
- 拜访记录：拜访目的必填，拜访日期不能晚于当前日期
- 「客户成功」前必须已生效
- 状态已成功/已失效后，主表不可编辑（子表也不可编辑）

#### 4.1.7 按钮定义

| 按钮  | 类型  | 触发事件 | 可见条件 |
| --- | --- | --- | --- |
| 新建预测客户 | ● PRIMARY | —   | 预测客户业务经理 |
| 批量生效 | ● PRIMARY | EVT-predict-activated | 已勾选「开立」记录 |
| 客户成功 | ● PRIMARY | EVT-predict-converted | 已生效状态 |
| 批量失效 | ■ DANGER | EVT-predict-expired | 已勾选「已生效」记录 |
| 重新开立 | ○ GHOST | —   | 已失效状态 |
| 删除预测客户 | ■ DANGER | —   | 开立状态 |

### 4.2 客户售后回访（模块编码：CRM-AF-RETURN）

#### 4.2.1 模块概述

业务经理对已成交客户进行售后回访，记录回访沟通内容，用于客户关系维护和需求挖掘。

#### 4.2.2 关联本体

- 主实体：CustomerReturnVisit（客户售后回访）
- 子表：CustomerVisitRecord（回访沟通记录，1:N）
- 引用：BD_Customer（客户档案，来自MDM）

#### 4.2.3 功能场景

**场景一：新建回访单**  
业务经理新建回访单，选择关联客户（来自MDM客户档案），填写拜访目的、拜访日期，保存。

**场景二：多次沟通记录**  
回访过程中有多轮沟通，业务经理在沟通记录子表中逐条补充沟通内容、问题反馈。

**场景三：提交回访单**  
业务经理完成回访后点击【提交回访单】，状态变更为「已提交」，提交后不可编辑。

**场景四：关闭回访单**  
业务经理或售后主管点击【关闭回访单】，状态变更为「已关闭」（终态）。

#### 4.2.4 页面结构

- **列表页**：表格展示，支持「开立/已提交/已关闭」状态筛选
- **新增/编辑页**：主表表单 + 沟通记录子表

#### 4.2.5 数据校验规则

- 回访单号：自动生成 `HF-YYYYMMDD-XXX`
- 客户编码：必填，下拉选择MDM客户档案
- 拜访目的：必填，最大500字符
- 拜访日期：必填，不能晚于当前日期
- 沟通记录：沟通主要内容必填，其他字段可选

#### 4.2.6 按钮定义

| 按钮  | 类型  | 触发事件 | 可见条件 |
| --- | --- | --- | --- |
| 新建回访单 | ● PRIMARY | —   | 售后回访业务经理 |
| 提交回访单 | ● PRIMARY | EVT-return-submitted | 开立状态 |
| 关闭回访单 | ○ GHOST | —   | 已提交状态 |

### 4.3 项目进度管理（模块编码：CRM-AF-PROJECT）

#### 4.3.1 模块概述

项目经理录入和管理设备项目的进度，分「外采」和「自制」两条线分别跟踪。外采线跟踪采购、付款、来票；自制线跟踪产线进度。外采/自制各自引用预置的节点配置。

#### 4.3.2 关联本体

- 主实体：ProjectProgress（项目进度）
- 子表A：ProjectProgressExternal（外采进度明细，1:N）
- 子表B：ProjectProgressInternal（自制进度明细，1:N）
- 引用：ProjectProgressNode（项目进度节点配置，仅读取）

#### 4.3.3 功能场景

**场景一：新建项目进度**  
项目经理新建项目进度，填写项目编码、项目名称、项目分类（外采/自制）、合同总金额。

**场景二：维护外采明细**  
选择「外采」分类后，在外采明细中新增记录，填写进度节点（从节点配置中选择）、开始/结束时间、合同金额、付款比例、来票金额等。

**场景三：维护自制明细**  
选择「自制」分类后，在自制明细中新增记录，填写进度节点、开始时间、进度描述等。

**场景四：更新来款金额**  
项目经理根据实际回款，在外采明细中更新「来款金额」，系统自动计算付款比例。

**场景五：关闭项目**  
项目经理确认项目完成后，点击【关闭项目】，状态变更为「已关闭」（终态）。

#### 4.3.4 页面结构

## 7\. 异常与容错设计

### 7.1 业务异常处理

| 异常场景 | 处理机制 |
| --- | --- |
| 重复提交审批 | 按钮点击后立即置灰，倒计时5秒后恢复，防止重复提交 |
| 派工时服务人员已达上限 | 提示「该工程师当前有X个进行中的工单」，允许强制派工（运营决策） |
| 点检项未全部通过 | 禁止点击「点检完成」，提示「有X项点检异常，请先处理」 |
| 质检未完成但试图销售确认 | 按钮不可用，提示「请先完成质检处理」 |
| 网络中断导致保存失败 | 前端本地缓存草稿，网络恢复后自动重试提交 |
| 审批超时 | 审批状态自动变为「已失效」，通知申请人重新提交 |

### 7.2 数据异常处理

| 异常场景 | 处理机制 |
| --- | --- |
| 客户档案被 MDM 删除 | 售后单据中客户字段置灰显示「（已失效）」，禁止新增引用该客户 |
| 节点配置被禁用 | 已引用该节点的明细行标记「节点已失效」，不影响历史数据，仅禁止新增引用 |
| 签字图片上传失败 | 提示上传失败，允许重试，不阻塞主流程 |

### 7.3 操作异常处理

| 异常场景 | 处理机制 |
| --- | --- |
| 误删重要记录 | 删除操作软删除（status标记），7天内可从回收站恢复 |
| 误关闭终态单据 | 已关闭的单据不提供「反关闭」操作，需管理员在后台处理 |
| 批量操作部分失败 | 展示失败行明细，成功的行正常执行，失败行保留原状态并提示原因 |

## 9\. 验收标准

### 9.1 预测客户模块

- [ ] 新增预测客户，编码格式为 `YC-YYYYMMDD-XXX`，当日第1条为001
  
- [ ] 业务经理默认带出当前登录人，不可修改
  
- [ ] 联系方式脱敏展示（手机号中间4位为\*）
  
- [ ] 「已生效」状态才允许点击「客户成功」
  
- [ ] 「客户成功」后记录锁定，不可编辑
  
- [ ] 「开立」状态才允许删除，有确认提示
  
- [ ] 拜访子表新增/编辑/删除正常
  

### 9.2 客户售后回访模块

- [ ] 新增回访单，编码格式为 `HF-YYYYMMDD-XXX`
  
- [ ] 客户下拉从MDM客户档案选择
  
- [ ] 「开立」状态才允许提交
  
- [ ] 提交后不可编辑
  
- [ ] 沟通记录子表增删改正常
  

### 9.3 项目进度模块

- [ ] 新增项目进度，编码格式为 `PJ-YYYYMMDD-XXX`
  
- [ ] 外采/自制分类切换后，明细Tab联动显示对应子表
  
- [ ] 外采明细「进度节点」从 ProjectProgressNode 中按分类筛选选择
  
- [ ] 付款比例自动计算 = 来款金额/合同总金额\*100%
  
- [ ] 「已关闭」状态不可逆
  

### 9.4 现场任务模块

- [ ] 新建现场任务，编码格式为 `SC-YYYYMMDD-XXX`
  
- [ ] 草稿状态未提交审批时，派工按钮不可用
  
- [ ] 提交审批后，审批状态变为「待审核」
  
- [ ] 审批通过后，派工按钮可用
  
- [ ] 派工后服务工程师可看到自己的派工任务
  
- [ ] 服务中才允许关闭任务
  
- [ ] 设备清单+任务明细子表增删改正常
  

### 9.5 整机调试模块

- [ ] 新建调试单，编码格式为 `ZJTS-YYYYMMDD-XXX`
  
- [ ] 点检明细由系统预置标准检查项，不允许用户新增
  
- [ ] 点检项未全部通过时，「点检完成」按钮不可用
  
- [ ] 点检全部通过后才能关闭
  
- [ ] 签字图片仅创建人和当前登录人可查看
  

### 9.6 设备维修模块

- [ ] 新建维修单，编码格式为 `WX-YYYYMMDD-XXX`
  
- [ ] 投诉子表和建议子表二选一，不能同时填写
  
- [ ] 有投诉/建议时，必须质检员填写完成才允许「质检完成」
  
- [ ] 质检完成后通知销售确认人
  
- [ ] 无投诉/建议时可直接进入销售确认
  
- [ ] 维修记录「问题是否解决」必须填「是」才能继续后续流程
