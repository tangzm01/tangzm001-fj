# 客户全貌功能详细需求方案

## 一、需求概述

### 1.1 业务目标

构建「客户全貌」功能模块，为销售、客服、交付管理等角色提供客户360°全景视图，实现：

- **一屏看清**：客户所有关键信息无需切换页面
- **预警提醒**：自动识别风险并推送给责任人
- **决策支撑**：提供数据依据支撑业务决策

### 1.2 用户角色

| 角色  | 主要诉求 | 关注模块 |
| --- | --- | --- |
| 销售人员 | 客户跟进、商机挖掘 | 基本信息、订单、沟通历史 |
| 客服人员 | 服务响应、问题处理 | 服务工单、沟通历史 |
| 交付经理 | 项目进度、风险预警 | 订单执行、生产进度、交付监控 |
| 财务人员 | 应收账款、回款跟进 | 财务结算、信用状况 |
| 管理层 | 客户健康度、风险把控 | 预警分析、客户健康度 |

### 3.1 本年订单总数 & 同比增长率

| 指标  | 计算公式 | 说明  |
| --- | --- | --- |
| **本年订单总数** | `COUNT(SM_SOMaster.HospitalID)`，筛选条件 `SM_SOMaster.DocDate BETWEEN '{本年1月1日}' AND '{今日}' AND SM_SOMaster.CustomerID = '{客户ID}'` | 仅统计生效/审核状态的销售订单，时间条件不能写死，需要根据当前时间获取本年的第一天 |
| **同比增长率** | `(本年订单数 - 去年同期订单数) / 去年同期订单数 × 100%` | 去年同期 = 去年同一日期区间 |

```sql
-- 本年订单总数
SELECT COUNT(1) AS order_count
FROM SM_SOWITH(NOLOCK)
WHERE CustomerID = @CustomerID
  AND DocDate >= DATEFROMPARTS(YEAR(GETDATE()), 1, 1)
  AND DocDate <= GETDATE()
  AND Status = 2;  -- 已审核

-- 去年同期订单数（用于同比）
SELECT COUNT(1) AS order_count_last_year
FROM SM_SOWITH(NOLOCK)
WHERE CustomerID = @CustomerID
  AND DocDate >= DATEFROMPARTS(YEAR(GETDATE()) - 1, 1, 1)
  AND DocDate < DATEFROMPARTS(YEAR(GETDATE()), 1, 1)
  AND Status = 2;
```

| 指标  | 计算公式 | 说明  |
| --- | --- | --- |
| **在途物流单** | `COUNT(SM_ShipLine.ID)`，筛选条件 `SM_ShipLine.ShipStatus IN ('shipped','in_transit') AND 客户=当前客户` | 出库但未签收的单据 |

### 3.6 信用额度占用率

| 指标  | 计算公式 | 说明  |
| --- | --- | --- |
| **信用额度占用率** | `(已占用金额 / 信用额度) × 100%` | 占用金额 = 在执行订单占用 + 应收账款占用 |
| **已占用金额** | `SUM(SM_SOMaster.OrderAmount WHERE Status=执行中) + SUM(AR_Receivable.UnRcdAmount)` | —   |
| **剩余额度** | `信用额度 - 已占用金额` | —   |

```sql
-- 信用额度占用率
SELECT
  @CreditLimit AS credit_limit,
  ISNULL(SUM(CASE WHEN s.Status IN (1,2) THEN s.OrderAmount ELSE 0 END), 0)
  + ISNULL(SUM(r.UnRcdAmount), 0) AS used_amount,
  (ISNULL(SUM(CASE WHEN s.Status IN (1,2) THEN s.OrderAmount ELSE 0 END), 0)
   + ISNULL(SUM(r.UnRcdAmount), 0)) * 100.0 / NULLIF(@CreditLimit, 0) AS usage_rate
FROM SM_SOs WITH(NOLOCK)
LEFT JOIN AR_Receivable r WITH(NOLOCK) ON r.CustomerID = s.CustomerID
WHERE s.CustomerID = @CustomerID;
```

## 四、客户等级（A/B/C）定义规则

> **定级维度：** 年交易额 + 合作年限 + 战略价值（综合评定）  
> **定级周期：** 每年1月1日重新评定，可手动调整

### 4.1 等级划分规则

| 等级  | 核心条件 | 特征描述 | 原型标识 |
| --- | --- | --- | --- |
| **⭐ A级（战略客户）** | 年交易额 ≥ 500万 **且** 合作年限 ≥ 3年 **或** 战略性客户（行业龙头/重点扶持） | 年度大客户，优先交付，专属服务通道 | `status st-green`，标签「⭐ A级」 |
| **✓ B级（优质客户）** | 年交易额 100万~500万 **或** 合作年限 ≥ 1年 | 稳定贡献客户，标准服务 | `status st-blue`，标签「✓ B级」 |
| **C级（普通客户）** | 年交易额 < 100万 **或** 新合作客户（< 1年） | 普通客户，控制赊销风险 | `status st-gray`，标签「C级」 |

### 4.2 A级客户附加条件（满足任一即可）

1.  本年累计订单金额 ≥ 500万元
2.  合作年限 ≥ 3年 **且** 年均交易额 ≥ 200万元

### 4.3 SQL 等级评定参考

```sql
WITH YearStats AS (
  SELECT
    c.CustomerID,
    c.CustomerName,
    ISNULL(SUM(CASE WHEN s.DocDate >= DATEFROMPARTS(YEAR(GETDATE()),1,1) THEN s.TotalAmount ELSE 0 END), 0) AS year_amount,
    DATEDIFF(YEAR, MIN(s.DocDate), GETDATE()) AS coop_years
  FROM MM_Customer c
  LEFT JOIN SM_SOs ON s.CustomerID = c.CustomerID AND s.Status = 2
  GROUP BY c.CustomerID, c.CustomerName
)
SELECT
  CustomerID,
  year_amount,
  CASE
    WHEN year_amount >= 5000000 AND coop_years >= 3 THEN 'A级'
    WHEN year_amount >= 1000000 THEN 'B级'
    ELSE 'C级'
  END AS grade
FROM YearStats;
```

## 五、客户风险等级（无/轻度/中度/重度）定义规则

> **定级维度：** 应收账款逾期情况 + 信用占用率 + 合同履约情况 + 服务投诉  
> **定级周期：** 实时计算，每日刷新  
> **判定优先级：** 从重原则（多条件触发时取最高等级）

### 5.1 风险等级划分规则

| 风险等级 | 触发条件（满足任一即触发） | 颜色标识 | 原型样式 |
| --- | --- | --- | --- |
| **✓ 无风险** | 应收账款无超期 **且** 信用占用率 < 80% **且** 无合同履约异常 | 绿色  | `risk-level none` |
| **⚡ 轻度** | 应收账款超期 1~~30天~~ **~~或~~** ~~信用占用率 80%~~90% | 浅绿  | `risk-level low` |
| **⚠ 中度** | 应收账款超期 31~60天 **或** 信用占用率 > 90% **或** 有合同延期记录 | 橙色  | `risk-level medium` |
| **⛔ 重度** | 应收账款超期 > 60天 **或** 连续超期 2次以上 **或** 客户已出现坏账迹象 | 红色  | `risk-level high` |

### 5.2 各等级详细判定逻辑

#### ✓ 无风险（绿色）

```
条件：超期天数 = 0 且 信用占用率 < 80% 且 无服务投诉记录
```

#### ⚡ 轻度风险（浅绿）

```
条件1：应收账款超期天数 ∈ [1, 30]
条件2：信用额度占用率 ∈ [80%, 90%) 且 无超期
条件3：近3个月有1次小额定金延期（< 5万）
```

#### ⚠ 中度风险（橙色）

```
条件1：应收账款超期天数 ∈ [31, 60]
条件2：信用额度占用率 ≥ 90%
条件3：有合同延期交货记录（延期 ≤ 15天）
条件4：近3个月有质量投诉（未关闭）
条件5：应收账款余额 > 信用额度的 80%
```

#### ⛔ 重度风险（红色）

```
条件1：应收账款超期天数 > 60天
条件2：连续2次以上超期（超期次数 ≥ 2）
条件3：信用额度占用率 = 100% 且 有超期
条件4：客户出现重大违约（合同中止/诉讼）
条件5：销售订单被暂停（客户信用冻结）
```

### 5.3 风险等级 SQL 判定

```sql
WITH OverdueStats AS (
  -- 逾期统计
  SELECT
    r.CustomerID,
    MAX(DATEDIFF(DAY, r.DueDate, GETDATE())) AS max_overdue_days,
    COUNT(CASE WHEN r.DueDate < GETDATE() AND r.UnRcdAmount > 0 THEN 1 END) AS overdue_count
  FROM AR_Receivable r WITH(NOLOCK)
  GROUP BY r.CustomerID
),
CreditUsage AS (
  -- 信用占用率
  SELECT
    c.CustomerID,
    @CreditLimit AS credit_limit,
    ISNULL(SUM(CASE WHEN s.Status IN (1,2) THEN s.OrderAmount ELSE 0 END), 0)
    + ISNULL(SUM(r.UnRcdAmount), 0) AS used_amount
  FROM MM_Customer c
  LEFT JOIN SM_SOs ON s.CustomerID = c.CustomerID
  LEFT JOIN AR_Receivable r ON r.CustomerID = c.CustomerID
  GROUP BY c.CustomerID
)
SELECT
  c.CustomerID,
  CASE
    WHEN ISNULL(o.max_overdue_days, 0) > 60 OR o.overdue_count >= 2 THEN '重度'
    WHEN ISNULL(o.max_overdue_days, 0) > 30 OR u.used_amount * 1.0 / NULLIF(u.credit_limit, 0) >= 0.9 THEN '中度'
    WHEN ISNULL(o.max_overdue_days, 0) > 0 OR u.used_amount * 1.0 / NULLIF(u.credit_limit, 0) >= 0.8 THEN '轻度'
    ELSE '无'
  END AS risk_level
FROM MM_Customer c
LEFT JOIN OverdueStats o ON o.CustomerID = c.CustomerID
LEFT JOIN CreditUsage u ON u.CustomerID = c.CustomerID
WHERE c.CustomerID = @CustomerID;
```

| 质量投诉未关闭 | \> 7 天 | 中度  | 升级处理 |
| 无订单周期 | ≥ 180 天 | 轻度  | 客户关怀触达 |
| 无订单周期 | ≥ 365 天 | 中度  | 客户流失预警 |

## 六、客户健康度综合评分规则

> **评分机制：** 4维度加权综合评分，满分100分  
> **权重配置：** 支持企业自定义（默认值：付款能力30% + 合作价值25% + 合作稳定性25% + 服务满意度20%）  
> **健康度等级：** A级（≥85分）/ B级（70~~84分）/ C级（60~~69分）/ D级（< 60分）

### 6.1 评分维度与权重

| 维度  | 默认权重 | 数据来源 | 满分条件 |
| --- | --- | --- | --- |
| 💰 付款能力 | 30% | AR_Receivable | 无超期 |
| 📈 合作价值 | 25% | SM_SOMaster | 年交易额行业前10% |
| 🤝 合作稳定性 | 25% | SM_SO+ MO_MOHead | 合作4年+ |
| 🔧 服务满意度 | 20% | CS_ServiceOrder | 满意度 ≥ 90分 |

### 6.2 各维度评分规则

#### 💰 付款能力（满分100分）

```
得分 = 100 - MIN(逾期天数 / 7, 10) × 10
     = 100 - ROUND(逾期天数 / 7, 0) × 10

计算示例：
- 逾期0天 → 100分
- 逾期7天 → 90分
- 逾期14天 → 80分
- 逾期35天 → 50分
- 逾期70天 → 0分（最低0分）
```

```sql
-- 付款能力得分（取最大逾期天数）
SELECT TOP 1
  100 - DATEDIFF(DAY, DueDate, GETDATE()) / 7 * 10 AS payment_score
FROM AR_Receivable WITH(NOLOCK)
WHERE CustomerID = @CustomerID
  AND UnRcdAmount > 0
ORDER BY DATEDIFF(DAY, DueDate, GETDATE()) DESC;
```

#### 📈 合作价值（满分100分）

```
得分 = 100 - (排名差10%等级差) × 10
     = 客户年交易额排名换算

计算逻辑：
- 客户年交易额排名 Top 10% → 100分
- 每降一个10%档位 → -10分
- 最低0分
```

```sql
WITH RankStats AS (
  SELECT
    CustomerID,
    SUM(TotalAmount) AS year_amount,
    RANK() OVER (ORDER BY SUM(TotalAmount) DESC) AS rn,
    COUNT(1) OVER() AS total_count
  FROM SM_SOWITH(NOLOCK)
  WHERE DocDate >= DATEFROMPARTS(YEAR(GETDATE()), 1, 1)
    AND Status = 2
  GROUP BY CustomerID
)
SELECT
  100 - ((rn - 1) * 10.0 / NULLIF(total_count, 0)) AS value_score
FROM RankStats
WHERE CustomerID = @CustomerID;
```

#### 🤝 合作稳定性（满分100分）

```
得分 = 100 - MAX(0, (4 - 合作年限)) × 15

计算示例：
- 合作4年+ → 100分
- 合作3年 → 85分
- 合作2年 → 70分
- 合作1年 → 55分
- 新客户（<1年）→ 按月折算，最低10分
```

#### 🔧 服务满意度（满分100分）

```
得分 = 满意度评分（来自CS_ServiceOrder满意度字段）

得分 = 100 - ROUND((90 - 满意度分) / 10, 0) × 20

计算示例：
- 满意度90分+ → 100分
- 满意度80分 → 80分
- 满意度70分 → 60分
- 满意度60分 → 40分
```

### 6.3 综合评分计算公式

```
综合评分 = Σ(各维度得分 × 权重)
         = 付款能力得分 × 30% + 合作价值得分 × 25%
         + 合作稳定性得分 × 25% + 服务满意度得分 × 20%
```

### 6.4 健康度等级划分

| 健康度等级 | 综合评分区间 | 颜色  | 说明  |
| --- | --- | --- | --- |
| **A级（优秀）** | 85 ~ 100 分 | 绿色  | 健康优质客户 |
| **B级（良好）** | 70 ~ 84 分 | 浅绿  | 正常合作客户 |
| **C级（一般）** | 60 ~ 69 分 | 橙色  | 需要关注 |
| **D级（预警）** | < 60 分 | 红色  | 重点预警客户 |

### 6.5 健康度评分 SQL

```sql
DECLARE @W_PAYMENT DECIMAL(3,2) = 0.30;  -- 付款能力权重
DECLARE @W_VALUE   DECIMAL(3,2) = 0.25;  -- 合作价值权重
DECLARE @W_STABLE  DECIMAL(3,2) = 0.25;  -- 合作稳定性权重
DECLARE @W_SATIS   DECIMAL(3,2) = 0.20;  -- 服务满意度权重

WITH ScorePayment AS (
  SELECT @CustomerID AS CustomerID,
    GREATEST(100 - DATEDIFF(DAY,
      (SELECT TOP 1 DueDate FROM AR_Receivable WHERE CustomerID = @CustomerID AND UnRcdAmount > 0 ORDER BY DueDate), GETDATE()) / 7 * 10, 0) AS score
),
ScoreValue AS (
  SELECT @CustomerID AS CustomerID,
    (SELECT TOP 1 100 - ((rn - 1) * 10.0 / NULLIF(total_count, 0))
     FROM (
       SELECT CustomerID, RANK() OVER(ORDER BY SUM(TotalAmount) DESC) AS rn,
         COUNT(1) OVER() AS total_count, SUM(TotalAmount) AS amt
       FROM SM_SOWITH(NOLOCK)
       WHERE DocDate >= DATEFROMPARTS(YEAR(GETDATE()), 1, 1) AND Status = 2
       GROUP BY CustomerID
     ) t WHERE CustomerID = @CustomerID) AS score
),
ScoreStable AS (
  SELECT @CustomerID AS CustomerID,
    GREATEST(100 - DATEDIFF(YEAR,
      (SELECT MIN(DocDate) FROM SM_SOWITH(NOLOCK) WHERE CustomerID = @CustomerID), GETDATE()) * 15, 0) AS score
),
ScoreSatis AS (
  SELECT @CustomerID AS CustomerID,
    ISNULL((SELECT AVG(SatisfactionScore) FROM CS_ServiceOrder WITH(NOLOCK)
     WHERE CustomerID = @CustomerID AND Status = 2), 80) AS score
)
SELECT
  p.score * @W_PAYMENT + v.score * @W_VALUE + s.score * @W_STABLE + t.score * @W_SATIS AS total_score,
  CASE
    WHEN p.score * @W_PAYMENT + v.score * @W_VALUE + s.score * @W_STABLE + t.score * @W_SATIS >= 85 THEN 'A级'
    WHEN p.score * @W_PAYMENT + v.score * @W_VALUE + s.score * @W_STABLE + t.score * @W_SATIS >= 70 THEN 'B级'
    WHEN p.score * @W_PAYMENT + v.score * @W_VALUE + s.score * @W_STABLE + t.score * @W_SATIS >= 60 THEN 'C级'
    ELSE 'D级'
  END AS health_grade
FROM ScorePayment p, ScoreValue v, ScoreStable s, ScoreSatis t;
```
