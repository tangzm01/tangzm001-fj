## 1.原始需求描述

需要在电脑端支持派工单工时的工时进行分摊，基于以上要求，出具对应电脑端工时分摊的需求方案

### **场景1：生产订单挂起**

- **触发条件**：订单级问题，如客户暂停、整体质量事故。
- **处理**：
    - 自动挂起所有未关闭的派工单及工序。
    - 对于已经完工的派工单/工序，如果尚未入库，可以允许入库（因为实际生产已经完成）。
    - 挂起后，禁止对任何被挂起对象进行新的业务操作。
    - 如果后续恢复生产，需要逐级解挂（先解挂订单，再解挂派工单和工序，或者设计为解挂订单时自动解挂下级对象）。

### **场景2：派工单挂起**

- **触发条件**：该派工单对应的任务暂停，比如班组人力不足、设备故障影响该派工单。
- **处理**：
    - 挂起该派工单下所有未完成工序。
    - 不影响同一生产订单下的其他派工单。
    - 该派工单下已完成的工序，如果符合入库条件，可以允许入库。
    - 挂起后，该派工单不能进行新的报工、领料等。

### **场景3：工序挂起**

- **触发条件**：特定工序出现问题，如设备故障、物料不良、工艺问题。
- **处理**：
    - 只挂起该工序，同一派工单下的其他工序可继续。
    - 该工序已报工的部分，如果检验合格，可以入库（即工序产出入库）。
    - 挂起后，该工序不能进行新的报工。

## 2.产品实现方案

挂起操作仅支持PC端操作，不支持平板端及移动端操作，且挂起按钮需要配置为权限按钮，支持进行权限配置

### 2.1生产订单-挂起

#### **触发条件**

- 订单级质量问题
- 客户需求变更
- 整体计划调整

**功能说明**

- 支持生产订单进行挂起，是否挂起（is_hold_release）改为是，记录挂起人（hold_person）及挂起时间（hold_time）填写挂起原因（hold_cause），挂起的订单仅支持解挂，其他不支持任何操作
- 挂起时修改对应生产订单状态为挂起，挂起联动挂起后续派工单及派工单工序信息，对应派工单信息改为挂起状态，派工单工序改为挂起状态，工序已开工的数量支持进行工序入库操作，可入库数量为已开工数量，若存在有完工申报单的数了则需要扣除，最大可进行工序入库数量=累计开工数量-已完工申报数量，工序入库后需要产生对应库存信息，不支持其他业务进行操作
- 挂起的派工单及派工单工序不支持进行其他操作，仅支持进行解挂操作
- 如果后续恢复生产，需要逐级解挂，先解挂订单，再解挂派工单和工序
- 进行工序入库的物料信息仅支持当前工序和下道工序进行领用，领用后需要扣除对应库存信息
- 仅挂起的生产订单支持解挂，解挂后需将生产订单是否挂起（is_hold_release）改为否，记录解挂时间（unhook_time）及解挂人（release_person）和解挂原因（release_cause）

#### **后续业务处理规则**

1.  **新派工单创建**：❌ 禁止
2.  **已有派工单执行**：❌ 禁止所有业务操作
3.  **工序报工**：❌ 禁止
4.  **物料领用**：❌ 禁止
5.  **工序入库**：⚠️ 特殊情况允许

#### **设计依据**

- 订单级挂起是最严格的管控，阻断所有生产活动
- 防止在订单暂停期间产生新的成本
- 保持生产现场与系统状态一致

### 2.2派工单-挂起

#### **触发条件**

- 该派工单对应的设备故障
- 班组人力不足
- 派工单质量问题

**关键数据项**

| 字段编码 | 字段名称 | 字段类型 | 必填  | 默认值规则 | 说明  |
| --- | --- | --- | --- | --- | --- |
| hold_cause | 挂起原因 | nvarchar | 否   | 填写  |     |
| hold_person | 挂起人 | nvarchar | 否   | 当前登录人 |     |
| hold_time | 挂起时间 | nvarchar | 否   | 当前操作时间 |     |
| release_cause | 解挂原因 | nvarchar | 否   | 填写  |     |
| release_person | 解挂人 | nvarchar | 否   | 当前登录人 |     |
| release_time | 解挂时间 | nvarchar | 否   | 当前操作时间 |     |
| is_hold_release | 是否挂起 | int | 否   | 否   | 挂起时为是，解挂是为否，数据库设置默认值为否且必填 |

#### **功能说明**

- 支持派工单进行挂起，是否挂起（is_hold_release）改为是，记录挂起人（hold_person）及挂起时间（hold_time）填写挂起原因（hold_cause），挂起的订单仅支持解挂，其他不支持任何操作

- 挂起的派工单及派工单工序不支持进行其他操作，仅支持进行解挂操作
- 如果后续恢复生产，需要逐级解挂，先解挂派工单和再解挂派工单工序
- 进行工序入库的物料信息仅支持当前工序和下道工序进行领用，领用后需要扣除对应库存信息
- 仅挂起的派工单支持解挂，解挂后需将派工单是否挂起（is_hold_release）改为否，记录解挂时间（release_time）及解挂人（release_person）和解挂原因（release_cause）

#### **后续业务处理规则**

1.  **本派工单工序报工**：❌ 禁止
2.  **其他派工单工序**：✅ 允许（状态正常时）
3.  **本派工单物料领用**：❌ 禁止
4.  **工序入库**：
    - 本派工单已完成工序：✅ 允许入库
    - 本派工单未完成工序：❌ 禁止入库
    - 其他派工单工序：✅ 正常入库

#### **设计依据**

- 实现生产任务的局部暂停
- 同一订单的不同派工可独立管理
- 适应多班组、多设备并行生产场景

### 2.3派工单工序-挂起

#### **触发条件**

- 特定工序质量问题
- 工序设备维护
- 工序物料短缺

**关键数据项**

| 字段编码 | 字段名称 | 字段类型 | 必填  | 默认值规则 | 说明  |
| --- | --- | --- | --- | --- | --- |
| hold_cause | 挂起原因 | nvarchar | 否   | 填写  |     |
| hold_person | 挂起人 | nvarchar | 否   | 当前登录人 |     |
| hold_time | 挂起时间 | nvarchar | 否   | 当前操作时间 |     |
| release_cause | 解挂原因 | nvarchar | 否   | 填写  |     |
| release_person | 解挂人 | nvarchar | 否   | 当前登录人 |     |
| release_time | 解挂时间 | nvarchar | 否   | 当前操作时间 |     |
| is_hold_release | 是否挂起 | int | 否   | 否   | 挂起时为是，解挂是为否，数据库设置默认值为否且必填 |

#### **功能说明**

- 支持派工单工序进行挂起，是否挂起（is_hold_release）改为是，记录挂起人（hold_person）及挂起时间（hold_time）填写挂起原因（hold_cause），挂起的订单仅支持解挂，其他不支持任何操作
- 挂起时修改对应派工单工序状态为挂起，工序已开工的数量支持进行工序入库操作，可入库数量为已开工数量，若存在有完工申报单的数了则需要扣除，最大可进行工序入库数量=累计开工数量-已完工申报数量，工序入库后需要产生对应库存信息，不支持其他业务进行操作
- 挂起的派工单及派工单工序不支持进行其他操作，仅支持进行解挂操作
- 如果后续恢复生产，需要解挂派工单工序
- 进行工序入库的物料信息仅支持当前工序和下道工序进行领用，领用后需要扣除对应库存信息

#### **后续业务处理规则**

1.  **本工序报工**：❌ 禁止
2.  **同一派工单其他工序**：✅ 允许（除非被其他因素挂起）
3.  **本工序物料领用**：❌ 禁止
4.  **工序入库**：
    - 本工序：⚠️ 特殊允许（已完工程度）
    - 前道工序：✅ 允许（如果已报工完成）
    - 后道工序：✅ 允许（如果有库存可用）

#### **设计依据**

- 最细粒度的生产控制
- 最小化异常影响范围
- 支持生产线的不平衡管理
