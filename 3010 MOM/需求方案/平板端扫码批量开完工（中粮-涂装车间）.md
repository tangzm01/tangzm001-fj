# 平板端扫码批量开完工（中粮-涂装车间）

## 一、业务背景与核心定义

### 1.1 业务背景

制造车间存在「一台设备+一个容器+多个派工单工序」的批量作业场景。工人需要：

- 在平板端快速选择/扫描容器
- 连续扫描多个派工单二维码
- 批量开工/完工多个工序
- 一键提交，减少重复操作

传统方式是逐个派工单逐个工序开工/完工，效率低、易出错。本方案通过「容器+扫码+批量」模式，实现**一屏多单、一次提交**。

### 1.2 核心定义

| 术语  | 定义  |
| --- | --- |
| **容器** | 生产现场用于存放工件的周转箱/托盘，关联设备、工位、组合单 |
| **组合单** | 多工序成组执行的排产单元（参考`mom_operation_combination`） |
| **派工单** | 具体工序的执行任务单，含产品、工序、数量、设备、班组等信息 |
| **批量开工** | 将当前容器中扫描的所有派工单工序，一次性记录开工时间和开工数量 |
| **批量完工** | 将当前容器中扫描的所有派工单工序，一次性记录完工时间和完工数量 |

### 1.3 适用终端

- **平板端**（本设计）：1280×800 分辨率，触控操作，车间工位固定部署
- 支持外接扫码枪（键盘模拟模式）或摄像头扫码

## 三、功能模块详细说明

### 3.1 容器列表

#### 3.1.1 页面标题

- 固定显示：`扫码开完工`
- 返回按钮：点击返回上一级

#### 3.1.2 容器扫码输入框

**UI 结构：**

```
┌────────────────────────────────────────────────────────────────────────┐
│ [扫码图标]  扫描或输入容器号，回车直接进入              [扫码按钮]     │
└────────────────────────────────────────────────────────────────────────┘
```

**交互逻辑：**

1.  支持手动输入容器号，回车确认（容器为设备的一种类型，具体数据用设备档案承载，用设备分类或类型区分）
2.  点击【扫码】按钮 → 弹出扫码弹窗
3.  扫码成功 → 直接进入页面2（批量开工），容器号自动填入
4.  容器不存在 → Toast 提示「容器号不存在，请确认」
5.  进入扫描开工页面默认显示扫码状态
6.  容器的使用状态可根据当前时是否有绑定的工序组合单判断（工序组合单不存在-容器状态为空闲，工序组合单状态为开工、开立-容器状态为使用中，已满状态暂不处理）

#### 3.1.3 布局切换按钮组

![](files/019facac-7261-76a0-9893-5b64f8b44214/image.png)

**三种布局：**

| 布局  | 列数  | 卡片信息 | 适用场景 |
| --- | --- | --- | --- |
| **大** | 2列  | 完整信息（容器号+状态+工位+组合单+容量+详情按钮） | 容器数量少，需要详细信息 |
| **中**（默认） | 4列  | 完整信息，卡片略小 | 常规场景 |
| **小** | 6列  | 仅容器号+状态+小图标 | 容器数量多，快速浏览 |

**交互逻辑：**

- 点击布局按钮 → 切换对应布局 → 按钮高亮
- 布局选择持久化（LocalStorage）

#### 3.1.4 容器卡片

**卡片字段：**

| 字段  | 说明  |
| --- | --- |
| 容器号 | 如 `52号`，大号加粗显示 |
| 状态  | `使用中`(琥珀色) / `空闲`(蓝色) / `已满`(红色) |
| 所在工位 | 如 `辊体车间 WC01` |
| 关联组合 | 当前容器绑定的组合单（非完工状态） |
| 规格容量 | 如 `250 件 / 80%`，空闲容器只显示容量 |

**交互逻辑：**

1.  点击卡片任意区域 → 进入屏幕2（扫码界面）
2.  进入时自动将容器号填入「容器」字段
3.  若容器已关联组合单，同时带入组合单信息

#### 3.1.5 容器统计

- 显示：`共 N 个容器`
- 数量实时统计当前显示的容器卡片数

![](files/019facac-7261-76a0-9893-5e30b773d34e/image.png)

**交互逻辑：**

### 3.3 开完工页面

#### 3.2.1 Tab 切换器

**UI 结构：**

![](files/019facac-7261-76a0-9893-62f9de7fa551/image.png)

**交互逻辑：**

- 默认选中【批量开工】，若是从组合单进行，则默认进入【批量完工】
- 点击 Tab → 切换面板，底部操作按钮同步切换
- Tab 状态影响：
    - Banner 内的「开工人/完工人」、「开工班组/完工班组」字段标签
    - 底部按钮：「批量开工」/「批量完工」
    - 工序列表的「本次开工」/「本次完工」输入标签

#### 3.2.2 页面信息

**UI 结构：**

**字段说明：**

| 区域  | 字段  | 说明  | 可编辑 |
| --- | --- | --- | --- |
| 容器区 | 容器号 | 当前选择的容器 | 点击可返回容器列表 |
| 设备区 | 当前设备 | 如 `数控车床-03号` | ✓ 点击编辑 |
| 设备区 | 所在车间 | 如 `辊体车间-WC01`，灰色小字 | 自动带出，不可编辑 |
| 信息栏 | 开工人/完工人 | 根据 Tab 动态显示 | ✓ 点击编辑，默认当前登录人对应用户及所在班组 |
| 信息栏 | 开工班组/完工班组 | 根据 Tab 动态显示 | ✓ 点击编辑，默认当前登录人对应用户及所在班组 |

**交互逻辑：**

1.  **容器号点击** → 返回屏幕0（容器列表），重新选择容器
2.  **设备点击** → 弹出编辑框，可修改设备名称
3.  **开工人/班组点击** → 弹出编辑框，可修改人员/班组
4.  **工序组合单扫码框**：
    - 手动输入派工单号，回车确认
    - 点击【扫码】按钮 → 弹出扫码弹窗
    - 扫码成功 → 调用接口查询派工单信息 → 生成工序卡片

#### 3.2.3 扫描统计区

**统计项：**

| 指标  | 说明  | 计算规则 |
| --- | --- | --- |
| 产品种类 | 已扫描的不同产品/工序种类数 | 统计卡片数量 |
| 待开工/待完工合计 | 所有卡片的开工/完工数量总和 | Σ(各卡片输入框的值) |

**交互逻辑：**

- 实时更新：卡片增删、数量修改时自动重新计算

#### 3.2.4 工序卡片列表

**UI 结构（单张卡片）：**

![](files/019facac-7261-76a0-9893-640b09b5ed09/image.png)

**卡片字段：**

| 区域  | 字段  | 说明  |
| --- | --- | --- |
| 标题行 | 派工单号 | 如 `P2024052002` |
| 标题行 | 工序编码 | 橙色标签，如 `OP010` |
| 标题行 | 工序名称 | 如 `铸造-粗坯` |
| 信息行 | 计划数量 | 如 `30件` |
| 信息行 | 待开工/待完工 | 红色高亮，如 `30件` |
| 信息行 | 原料信息 | 如 `Φ133钢管` |
| 输入行 | 本次开工/完工 | 数字输入框，默认=待开工数 |
| 输入行 | 上游完工数 | 参考提示，如 `30件` |

**交互逻辑：**

1.  **新增卡片**：
    - 扫描派工单 → 调用接口获取派工单工序信息 → 添加卡片
    - 同一派工单工序重复扫描 → Toast 提示「该派工单已在清单中」
    - 若识别扫描的是容器则进行提示，当前扫描信息为进行保存时是否替换
2.  **删除卡片**：
    - 点击右上角 \[×\] 按钮 → 弹出二次确认弹窗
    - 确认弹窗内容：
        
        ```
        ┌─────────────────────────────────────────┐
        │ ⚠ 确认移除此标签？                      │
        │   移除后该标签不会参与本次批量完工/开工，    │
        │   您可重新扫码加入。                    │
        │                                         │
        │   P2024052002  OP010  铸造-粗坯        │
        │                                         │
        │              [取消]  [确认移除]         │
        └─────────────────────────────────────────┘
        ```
        
    - 确认后 → 卡片淡出删除 → 更新统计
    - 若当前信息已进行保存则需要是删除对应工序组合单明细信息
3.  **数量输入**：
    - 输入框默认值 = 待开工/待完工数量
    - 输入值 > 待开工/待完工数量 → 输入框变红，显示警告
    - 输入值 ≤ 待开工/待完工数量 → 正常提交
    - 支持键盘上下键调整

#### 3.2.5 底部操作按钮

**按钮功能说明：**

| 按钮  | 功能  | 交互逻辑 |
| --- | --- | --- |
| **打印标签** | 打印当前扫描的工序标签 | 点击 → Toast「正在打印标签...」→ 调用打印机接口 |
| **保存** | 保存当前扫码信息为开立状态 | 点击 → Toast「已保存草稿」→ 数据存入数据库，生成对应工序组合单 |
| **批量开工** | 提交批量开工记录 | 点击 → 校验 → 调用接口 → Toast「批量开工提交成功！共 XX 件」 |
| **批量完工** | 提交批量完工记录 | 点击 → 校验 → 调用接口 → Toast「批量完工确认成功！共 XX 件」 |

- **打印标签** ：打印对应功能工序组合单信息，批量开工页面，数据进行保存后，支持进行打印，若数据未进行保存就是暂未生成对应的工序组合单则不支持进行对应，支持多次打印，打印样式待定
- **保存** ：修改当前页面显示工序组合单信息及明细信息，仅开立状态支持修改
- **批量开工：**
    - 有剩余可开工数量的支持操作开工，支持多选进行开工根据所选项匹配对应的工序信息，进行开工，生成对应的开工操作记录，记录对应的开工时间及开工人，设备及其他信息则为前置派工时做选择的信息进行存储至开工记录中。若无对应数据值则需要进行提示，填写对应设备信息及其他信息，开工人员及班组可默认取当前登录人对应的信息
    - 开工时需校验当前工序是否支持开工，例如是否还有开工数量剩余等，参照平板端开工时的校验同步实现。
    - 兼容工序报检相关功能
    - 修改当前工序组合单状态及行状态

- **批量完工：**
    - 已确认状态的支持操作完工，支持多选进行完工根据所选项匹配对应的工序组合工单明细，进行完工，生成对应的完工操作记录，记录对应的完工时间，设备及其他信息则为当前排产时做选择的信息进行存储至完工记录中，按照对应工序配置的工时生成方式如果为时间差额，则需要自动生成对应的工时记录，工时为完工时间-开工时间
    - 完工时需校验当前工序是否支持完工，例如是否还有完工数量剩余等，参照平板端完工时的校验同步实现

**提交校验规则：**

| 校验项 | 规则  | 错误提示 |
| --- | --- | --- |
| 卡片数量 | 至少有 1 张卡片 | 「请先扫描派工单」 |
| 设备必填 | 设备名称不为空 | 「请选择设备」 |
| 人员必填 | 开工人/完工人不为空 | 「请填写开工人/完工人」 |
| 数量必填 | 每张卡片数量 > 0 | 「请填写开工/完工数量」 |
| 数量上限 | 每张卡片数量 ≤ 待开工/待完工数 | 「开工数量不能超过待开工数量」 |

## 四、扫码弹窗与交互

### 4.1 通用扫码弹窗

**触发场景：**

- 容器列表页点击【扫码】按钮
- 扫码界面 Banner 内点击【扫码】按钮

**交互逻辑：**

1.  弹窗显示 → 输入框自动聚焦
2.  扫码枪扫码 → 输入框接收条码内容 → 自动触发提交
3.  点击背景遮罩 → 关闭弹窗

### 4.2 派工单扫码全屏弹层

**UI 结构：**

![](files/019facac-7261-76a0-9893-6a5429b8c118/image.png)

**交互逻辑：**

1.  扫码成功 → 弹层显示派工单大卡
2.  用户可修改「本次开工」数量
3.  点击【确认加入】→ 卡片加入下方工序列表 → 弹层关闭
    1.  初次加入时需校验当前是否存在对应的容器的工序组合单，若不存在则创建对应容器的工序组合单主表信息及当前扫码工序的子表信息。若存在则往当前容器对应的工序组合单追加行信息
4.  点击【取消】或背景 → 弹层关闭，不加入清单
5.  连续扫码 → 新卡片替换当前大卡（不累加）
6.  扫码时，需校验当前派工单工序是否已扫描过，若已存在当前工序组合单时，需进行提示
7.  支持扫码工序组合单码和派工单工序码，若扫描对应工序组合单码则显示对应工序组合单信息且不显示弹框信息

## 五、数据字段与接口

### 5.1 容器数据结构

| 字段  | 类型  | 说明  |
| --- | --- | --- |
| `containerNo` | String | 容器号，如 `52号` |
| `status` | Enum | `using`（使用中）/ `idle`（空闲）/ `full`（已满） |
| `workCenter` | String | 所在工位，如 `辊体车间 WC01` |
| `comboNo` | String | 关联组合单号，如 `ZH202604001` |
| `capacity` | Object | `{ total: 250, used: 200, percent: 80 }` |

### 5.2 派工单工序数据结构

| 字段  | 类型  | 说明  |
| --- | --- | --- |
| `dispatchNo` | String | 派工单号，如 `P2024052002` |
| `processCode` | String | 工序编码，如 `OP010` |
| `processName` | String | 工序名称，如 `铸造-粗坯` |
| `planQty` | Integer | 计划数量 |
| `pendingQty` | Integer | 待开工/待完工数量 |
| `materialInfo` | String | 原料信息，如 `Φ133钢管` |
| `upstreamQty` | Integer | 上游完工数量（参考） |
| `inputQty` | Integer | 本次开工/完工数量（用户输入） |

## 七、异常处理与提示

### 7.1 异常场景

| 场景  | 提示  | 处理  |
| --- | --- | --- |
| 容器号不存在 | 「容器号不存在，请确认」 | 清空输入框 |
| 派工单工序不存在 | 「派工单不存在，请确认」 | 清空输入框 |
| 派工单工序已在清单 | 「该派工单已在清单中」 | 不重复添加 |
| 网络异常 | 「网络异常，请稍后重试」 | 允许重试 |
| 提交失败 | 「提交失败：{错误原因}」 | 保留数据，允许重试 |

### 7.2 Toast 提示规范

| 类型  | 样式  | 示例  |
| --- | --- | --- |
| 成功  | 绿色边框 | 「✅ 批量开工提交成功！共 230 件」 |
| 失败  | 红色边框 | 「❌ 提交失败：网络异常」 |
| 警告  | 橙色边框 | 「⚠ 请先扫描派工单」 |
| 信息  | 灰色边框 | 「已保存草稿」 |
