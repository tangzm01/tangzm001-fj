# 料品分类处理需求方案

# 概述

料品分类处理是针对 CJC 系统中基础档案管理的重要功能模块，旨在大规模料品及分类档案的场景下，提供清晰的分类状态管理和业务联动控制能力。

系统需同时满足两类业务场景：其一，分类失效仅出于归档目的，料品保持有效；其二，分类失效伴随下级料品同步失效。针对基础档案在业务单据中的可选范围，系统提供"全量查询"与"有效查询"两种模式，由前台控制是否默认过滤未启用的基础档案数据。

# 业务主线

## 场景一：分类失效用于纯粹归档

**业务背景**：某旧产品线停产，对应分类不再接收新料品，但旧料品仍需支持维修、售后及历史数据分析等场景。

**处理方式**：

- 料品保持有效，分类下所有料品的"有效/失效"状态**不变**
- 系统管理员或数据管理员将料品**批量转移**至另一个有效分类（如"历史产品-归档"或"停产产品"）

**业务影响**：

- 料品仍可被查询、被旧 BOM 引用、被历史单据查询到
- 料品存在于逻辑清晰的"归档"分类中，不干扰新业务开展

---

## 场景二：分类失效伴随所有料品同步失效

**业务背景**：试生产批次的所有临时料品，随试生产结束而全部作废。

**处理方式**：

- 提供批量操作，将料品整体失效
- 或批量转移至指定的停用分类

---

## 场景三：基础档案在业务单据中的查询控制

**业务背景**：CJC 中的基础档案（如部门档案）本身支持"启用/未启用"状态，失效的基础档案在业务单据中不应被选到，只能从上游单据带出。

**处理方式**：

- 失效的基础档案在**生产订单、完工申报、成品入库**等业务单据中不可选
- 所有基础档案建议统一调整其在业务单据中的查询范围

# 名词解释

| 名词  | 说明  |

| 料品分类 | 料品的逻辑分组单位，用于管理和查找料品 |

| BOM | 物料清单（Bill of Materials），生产制造用关键数据 |

# 功能详述

## 料品分类

### 功能描述

1、将料品分类档案从料品档案（元）菜单中独立出来，单独提供维护入口，便于管理员集中管理分类状态。

2、料品分类失效后，把其对应的料品也失效。

### 功能说明

- 业务菜单：基础设置 -> 库存相关 -> 料品分类
- 业务按钮：
    - 生效：支持单行、批量生效，生效后“是否失效”更新为 否。
    - 失效：支持单行、批量失效，失效后“是否失效”更新为 是。
    - 新增：支持单行、批量新增。
    - 数据同步：从第三方系统同步料品分类。
    - 编辑：支持单行、批量编辑。
    - 删除：支持单行、批量删除，若被其他菜单引用则不可删除。

## 基础档案业务单据查询控制

### 功能描述

针对支持"生效/失效"状态的基础档案，统一控制在业务单据中的查询范围，失效的档案不可被选到，但可以被带到下游单据。

举例：料品档案可以失效，则失效的料品，在生产订单，完工申报，成品入库时，不能被选到，只能从上游单据带出。

### 解决方式

**~~方案一：双接口分离~~**

- ~~提供两个方法给前端：~~
- `查询所有`~~\~~~~：返回全量数据（含未启用）~~
- `查询生效`~~\~~~~：仅返回启用状态数据~~
- ~~前端按需调用~~

**方案二：参数化查询（推荐）**

- 后台提供**最全的查询方法**
- 前端支持**参数配置**控制是否默认过滤
- 同时支持查看全部档案的能力

### 适用范围

| 模块  | 是否支持生效控制 | 业务单据过滤 |
| --- | --- | --- |
| MOM | ✅   | ✅ BOM / 工艺路线 / 生产订单 / 派工单 / 完工申报 等业务单据查询过滤 |
| WMS | ✅   | ✅ 料品建档 / 采购订单 / 采购送货 / 采购收货 / 成品入库等业务单据查询过滤 |
| SRM | ✅   | ✅ 销售订单 / 比价单等业务单据查询过滤 |
| 其他模块 | 建议统一评估 | 建议统一处理 |

### 接口设计原则

- 后台接口返回**完整数据**，不默认过滤
- 前端通过配置项 `archive_query_filter_enabled: true/false` 控制默认行为
- 用户可在单据界面手动切换"显示全部 / 仅显示生效"选项
