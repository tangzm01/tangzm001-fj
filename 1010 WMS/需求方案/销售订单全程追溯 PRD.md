## 2\. 功能概述

### 2.1 业务背景

销售订单生成后，业务人员通常需要在多个功能页面分别查询出货计划、发货单、装箱单和发运单，难以快速掌握订单当前所处履约节点，也难以回答以下问题：

- 订单是否已经安排出货；
- 计划出货数量和实际发货数量分别是多少；
- 一张订单分几次发货；
- 每次发货对应哪些装箱单；
- 货物由哪张发运单承运；
- 当前是否已发运、在途或签收；
- 某张业务单据的具体内容是什么。

因此，需要以销售订单为追溯入口，汇总展示订单基本信息及其下游履约单据，形成从订单到发运的完整业务链路，并支持从单据编码快速穿透至源单据页面。

### 2.2 功能目标

1.  以销售订单为追溯主对象，集中展示订单信息和履约数据；
2.  支持标准计划链路：“销售订单 → 出货计划 → 销售订单发货单 → 装箱单 → 发运单”；
3.  支持直接发货链路：“销售订单 → 销售订单发货单 → 装箱单 → 发运单”；
4.  支持销售订单不经过出货计划，直接关联或生成销售发货单；
5.  支持一张销售订单对应多条出货计划、多张发货单、多张装箱单和多张发运单；
6.  展示计划数量、发货数量、装箱数量和发运数量等关键履约指标；
7.  展示各节点业务状态和关键时间，帮助用户判断订单当前进度；
8.  支持点击业务单据编码，在新浏览器页签打开对应单据详情；
9.  减少用户跨模块检索和人工核对，提高订单查询及客户响应效率。

- 不改变现有源单据的业务流程和状态机；
- 不在本期重新定义各业务模块的单据编码规则。

### 2.5 核心业务规则

| 规则项 | 规则内容 |
| --- | --- |
| 追溯主对象 | 以销售订单作为查询和展示主对象。 |
| 数据关系 | 销售订单与出货计划、发货单、装箱单、发运单均按一对多关系展示；发货单既可来源于出货计划，也可直接来源于销售订单。 |
| 可选节点 | 出货计划为可选业务节点。不存在出货计划时，销售订单可直接关联销售发货单，追溯链路不得中断。 |
| 数据来源 | 追溯页面只汇总源业务单据数据，不在追溯页维护源数据。 |
| 关联原则 | 优先使用稳定的内部主键或关联表建立关系，单据编码仅用于展示和跳转，不建议作为唯一关联键。 |
| 编码穿透 | 可访问的单据编码显示为链接，点击后在新页签打开对应源单据详情页。 |
| 权限校验 | 追溯数据展示和源单据跳转均需执行当前用户的数据权限与功能权限校验。 |
| 状态展示 | 展示源单据原始状态；跨模块履约节点可通过统一状态映射展示。 |
| 数量口径 | 订单数量、计划数量、发货数量、装箱数量、发运数量按订单明细行和单位进行统计。 |
| 多单位 | 若业务存在主辅单位，必须分别展示或完成统一换算，不得直接将不同单位数量相加。 |
| 排序规则 | 各单据分区默认按业务日期倒序、单据编码倒序展示。 |
| 撤销单据 | 已作废、已撤销、已红冲单据是否计入汇总由业务口径决定；默认不计入有效履约数量，但保留追溯记录和状态。 |

## 3\. 用户使用流程

### 3.1 主流程

| 步骤  | 用户操作 | 系统处理 | 结果  |
| --- | --- | --- | --- |
| 1   | 进入“销售订单全程追溯”页面 | 加载查询条件和默认数据范围 | 展示追溯查询页面 |
| 2   | 输入销售订单编码、客户、日期等条件并查询 | 按用户权限查询销售订单 | 展示符合条件的订单列表 |
| 3   | 点击订单编码或“查看追溯” | 查询订单主信息、订单明细及关联业务单据 | 打开订单追溯详情页 |
| 4   | 查看订单履约概览 | 汇总计划、发货、装箱和发运数量及状态 | 展示履约进度和节点摘要 |
| 5   | 展开出货计划区域 | 查询该订单关联的全部出货计划 | 展示出货计划列表 |
| 6   | 展开发货单明细区域 | 查询该订单关联的全部发货单及明细 | 展示发货执行情况 |
| 7   | 展开装箱单区域 | 查询关联装箱单及装箱摘要 | 展示包装执行情况 |
| 8   | 展开发运单区域 | 查询关联发运单、承运和签收信息 | 展示物流执行情况 |
| 9   | 点击任一单据编码 | 校验功能权限、数据权限及目标路由 | 在新页签打开源单据详情页 |

### 3.2 订单追溯链路

```text
销售订单
  ├─ 标准计划链路
  │    ├─ 出货计划 1
  │    │    ├─ 销售订单发货单 1
  │    │    │    ├─ 装箱单 1
  │    │    │    └─ 发运单 1
  │    │    └─ 销售订单发货单 2
  │    │         ├─ 装箱单 2
  │    │         └─ 发运单 2
  │    └─ 出货计划 2
  │         └─ 销售订单发货单 3
  │              ├─ 装箱单 3
  │              └─ 发运单 3
  │
  └─ 直接发货链路（无出货计划）
       └─ 销售订单发货单 4
            ├─ 装箱单 4
            └─ 发运单 4
```

> 出货计划为可选节点。销售发货单既可以由出货计划下推或关联生成，也可以直接由销售订单下推或关联生成。系统必须同时支持“销售订单 → 出货计划 → 销售发货单”和“销售订单 → 销售发货单”两种来源链路。实际业务还可能出现一个发货单对应多个装箱单，或多个发货单合并到一张发运单，系统应以真实关联数据为准，不强制固定层级数量。

### 3.3 单据编码打开流程

1.  用户在追溯详情页点击单据编码；
2.  系统识别单据类型和单据内部主键；
3.  系统校验用户是否具备目标功能访问权限；
4.  系统校验用户是否具备该单据的数据权限；
5.  校验通过后构造对应详情页路由；
6.  浏览器在新页签打开单据详情；
7.  原追溯页保持查询条件、滚动位置和展开状态不变。

### 3.4 异常分支

- **未查询到销售订单**：展示空状态，不显示追溯详情。
- **订单暂无下游单据**：对应分区显示“暂无出货计划/发货单/装箱单/发运单”。
- **源单据已作废或撤销**：保留记录并明确展示作废/撤销状态，是否计入汇总按业务规则执行。
- **用户无功能权限**：单据编码不展示为可点击链接，或点击后提示无访问权限。
- **用户无数据权限**：不得通过拼接 URL 越权访问单据，服务端返回无权限提示。
- **目标单据已删除或路由失效**：新页签展示“单据不存在或已失效”，追溯页不受影响。
- **关联数据不完整**：展示已获取的单据，并标注“关联信息不完整”，记录异常日志。
- **接口查询超时**：对应分区显示加载失败和重试入口，不影响其他已成功分区。

## 4\. 功能详细描述

### 4.1 查询入口与销售订单列表

#### 4.1.1 查询条件

| 字段  | 控件  | 是否必填 | 查询方式 | 说明  |
| --- | --- | --- | --- | --- |
| 销售订单编码 | 输入框 | 否   | 精确/模糊 | 支持按完整编码或关键字查询，具体方式由产品确认 |

| 销售员 | 人员参照 | 否   | 精确  | 默认可带入当前用户 |

| 字段  | 说明  | 交互  |

| 已计划数量 | 有效出货计划数量汇总 | 只读  |
| 已发货数量 | 有效发货单数量汇总 | 只读  |
| 已发运数量 | 有效发运单数量汇总 | 只读  |
| 履约状态 | 根据节点和数量计算或映射 | 状态标签 |
| 操作  | 查看追溯 | 打开追溯详情 |

#### 4.1.3 查询与分页规则

- 用户至少输入一个有效查询条件后方可执行大范围查询，是否强制由实施确认；
- 默认仅查询用户有权访问的销售组织、客户或销售员数据；
- 列表支持分页、页码切换和每页条数设置；
- 默认按订单日期倒序、销售订单编码倒序；
- 查询条件应在进入追溯详情后保留，返回列表时恢复原查询状态；
- 大数据量场景不得一次性加载全部订单及全部明细。

### 4.3 出货计划

#### 4.3.1 功能说明

展示当前销售订单关联的全部出货计划及计划明细。一张销售订单允许分多次制定出货计划，同一出货计划也可能包含多个订单明细行。

#### 4.3.2 建议字段

| 字段  | 说明  | 交互  |
| --- | --- | --- |
| 出货计划编码 | 出货计划单据编码 | 可点击，新页签打开出货计划详情 |
| 计划日期 | 计划创建或业务日期 | 只读  |
| 计划出货日期 | 预计出货时间 | 只读  |
| 计划状态 | 草稿、已审核、执行中、已完成、已作废等 | 状态标签 |
| 订单行号 | 关联销售订单明细行 | 只读  |
| 物料编码/名称 | 计划出货物料 | 只读  |
| 计划数量 | 当前计划明细数量 | 带单位 |
| 已执行数量 | 已转发货单或已发货数量 | 带单位 |
| 未执行数量 | 计划数量－已执行数量 | 带单位 |
| 仓库  | 计划出货仓库 | 只读  |
| 创建人/创建时间 | 单据审计信息 | 只读  |

#### 4.3.3 业务规则

- 仅统计与当前订单或订单明细建立有效关联的出货计划；
- 作废、撤销计划默认不计入已计划数量，但保留记录并展示状态；
- 计划数量超出订单剩余可计划数量时，在追溯页显示异常标识；
- 一张计划包含多条当前订单明细时，应逐行展示；
- 同一计划编码可合并展示主信息，但必须能够查看全部关联明细。

### 4.4 销售订单发货单明细

#### 4.4.1 功能说明

展示当前销售订单关联的发货单及其明细，反映订单实际发货执行情况。一张销售订单允许多次、分批发货。

#### 4.4.2 建议字段

| 字段  | 说明  | 交互  |
| --- | --- | --- |
| 发货单编码 | 销售订单发货单编码 | 可点击，新页签打开发货单详情 |
| 发货日期 | 发货单业务日期 | 只读  |
| 发货状态 | 草稿、已审核、已出库、已完成、已作废等 | 状态标签 |
| 来源出货计划 | 来源计划编码 | 可点击时新页签打开计划详情 |
| 订单行号 | 关联销售订单明细行 | 只读  |
| 物料编码/名称 | 发货物料 | 只读  |
| 发货数量 | 当前发货明细数量 | 带单位 |
| 仓库  | 发货仓库 | 只读  |
| 批次号 | 发货批次，若有 | 只读  |
| 收货单位 | 收货客户或地点 | 只读  |
| 出库状态 | 未出库、部分出库、已出库 | 状态标签 |
| 制单人/审核人 | 单据责任人员 | 只读  |

#### 4.4.3 业务规则

- 发货数量按有效发货单明细汇总；
- 发货单支持两类来源：由出货计划下推/关联生成，或由销售订单直接下推/关联生成；
- 发货单直接来源于销售订单时，来源出货计划允许为空，但销售订单头、销售订单行关联必须完整；
- 作废、撤销、红冲单据默认不计入有效发货数量，但必须保留追溯记录；
- 发生退货或负数发货时，是否冲减已发货数量由业务口径确认；
- 同一销售订单明细可关联多张发货单；
- 发货数量超过订单数量时显示“超发”异常标识；
- 发货单没有来源出货计划时仍可展示，但标记“无出货计划来源”。

### 4.5 装箱单

#### 4.5.1 功能说明

展示销售订单或发货单关联的装箱单，帮助用户查询本次交付的箱数、包装信息和装箱数量。

#### 4.5.2 建议字段

| 字段  | 说明  | 交互  |
| --- | --- | --- |
| 装箱单编码 | 装箱业务单据编码 | 可点击，新页签打开装箱单详情 |
| 装箱日期 | 装箱业务日期 | 只读  |
| 装箱状态 | 待装箱、装箱中、已完成、已作废等 | 状态标签 |
| 关联发货单 | 发货单编码 | 可点击，新页签打开发货单详情 |
| 箱数  | 装箱单总箱数 | 数值  |
| 箱号范围 | 起始箱号至结束箱号，若有 | 只读  |
| 物料编码/名称 | 装箱物料 | 只读  |
| 装箱数量 | 当前装箱明细数量 | 带单位 |
| 包装类型 | 箱、托、桶等 | 只读  |
| 毛重/净重 | 装箱重量 | 带重量单位 |
| 体积  | 包装体积 | 带体积单位 |
| 装箱人/完成时间 | 装箱执行信息 | 只读  |

#### 4.5.3 业务规则

- 一个发货单可对应多张装箱单；
- 一张装箱单是否允许包含多张发货单，由现有业务模型决定；
- 有效装箱数量原则上不得大于对应有效发货数量，超出时显示异常标识；
- 作废装箱单不计入已装箱数量，但保留追溯记录；
- 若系统未维护箱级明细，本期只展示装箱单及汇总信息。

### 4.6 发运单

#### 4.6.1 功能说明

展示销售订单、发货单或装箱单关联的发运单，反映货物从发运准备到签收的物流执行状态。

#### 4.6.2 建议字段

| 字段  | 说明  | 交互  |
| --- | --- | --- |
| 发运单编码 | 发运业务单据编码 | 可点击，新页签打开发运单详情 |
| 发运日期 | 实际或计划发运日期 | 只读  |
| 发运状态 | 待发运、已发运、运输中、已到达、已签收、已取消等 | 状态标签 |
| 关联发货单 | 关联发货单编码 | 可点击，新页签打开发货单详情 |
| 关联装箱单 | 关联装箱单编码 | 可点击，新页签打开装箱单详情 |
| 发运数量 | 当前发运明细数量 | 带单位 |
| 承运商 | 物流公司或承运单位 | 只读  |
| 运输方式 | 公路、铁路、海运、空运等 | 只读  |
| 车牌号/运单号 | 车辆或物流运单标识 | 按权限展示 |
| 司机/联系电话 | 运输联系人 | 敏感字段按权限展示 |
| 发货地址 | 发运起点 | 只读  |
| 收货地址 | 交付地点 | 只读  |
| 签收人/签收时间 | 签收信息，若有 | 只读  |

#### 4.6.3 业务规则

- 一张销售订单可由多张发运单分批发运；
- 多张发货单可根据实际业务合并至一张发运单；
- 发运数量应通过发运明细与销售订单明细的关联进行汇总；
- 已取消发运单默认不计入已发运数量，但保留记录；
- 签收状态应以源发运单或物流回传状态为准；
- 本期仅展示已有物流状态，不实现实时地图轨迹。

### 4.7 单据编码穿透

#### 4.7.1 可穿透单据

| 单据类型 | 可点击编码 | 目标页面 |
| --- | --- | --- |
| 销售订单 | 销售订单编码 | 销售订单详情页 |
| 出货计划 | 出货计划编码 | 出货计划详情页 |
| 销售订单发货单 | 发货单编码 | 发货单详情页 |
| 装箱单 | 装箱单编码 | 装箱单详情页 |
| 发运单 | 发运单编码 | 发运单详情页 |

#### 4.7.2 交互要求

- 单据编码使用链接色、下划线或悬停样式标识可点击；
- 鼠标悬停显示“在新页签打开单据详情”；
- 点击后使用新浏览器页签打开；
- 原追溯页面不得刷新或丢失查询状态；
- 目标页面默认以只读详情模式打开，是否允许编辑由目标页面权限决定；
- 用户无权限时，不得仅依靠前端隐藏，服务端必须再次校验；
- 若目标系统支持统一门户路由，应使用统一路由服务，不在前端硬编码完整域名；
- 新页签链接必须避免反向控制原页面。

#### 4.7.3 URL建议

```text
/{module}/{documentType}/detail/{documentId}
```

示例仅用于说明：

```text
/sales/sales-order/detail/{salesOrderId}
/sales/shipment-plan/detail/{shipmentPlanId}
/sales/delivery-order/detail/{deliveryOrderId}
/warehouse/packing-list/detail/{packingListId}
/logistics/dispatch-order/detail/{dispatchOrderId}
```

> 最终路由需以现有系统菜单、模块编码和权限体系为准。

### 4.8 状态与履约进度

#### 4.8.1 建议履约状态

| 履约状态 | 判断建议 |
| --- | --- |
| 未计划 | 有效已计划数量为0 |
| 已计划 | 已计划数量大于0，且有效已发货数量为0 |
| 部分发货 | 已发货数量大于0且小于订单数量 |
| 已发货 | 已发货数量达到订单数量，但尚未全部发运或签收 |
| 部分发运 | 已发运数量大于0且小于订单数量 |
| 已发运 | 已发运数量达到订单数量，尚未确认全部签收 |
| 部分签收 | 存在已签收发运记录，但订单未全部签收 |
| 已完成 | 按业务规则确认全部发运或全部签收完成 |
| 已关闭 | 销售订单已关闭，剩余数量不再执行 |
| 已取消 | 销售订单已取消或作废 |
| 异常  | 存在超计划、超发、超装箱、超发运或关联断链 |

> “已完成”以全部发运还是全部签收为判断标准，需由业务和实施顾问确认。

### 4.9 权限与数据安全

| 对象  | 查看权限 | 点击穿透 | 敏感字段 |

## 7\. 原始需求描述

### 7.1 用户原始需求

> B端工业互联网，编写销售订单全程追溯 PRD 文档，包括订单信息及基本信息、出货计划、销售订单发货单明细、装箱单、发运单，并支持点击单据编码打开单据页面。

### 7.2 需求结构化整理

1.  建设面向 B 端工业互联网平台的销售订单全程追溯功能；
2.  以销售订单为追溯入口；
3.  展示销售订单信息及基本信息；
4.  展示销售订单明细和履约数量；
5.  展示关联出货计划；出货计划为可选节点；
6.  展示关联销售订单发货单明细，支持由出货计划生成或由销售订单直接生成；
7.  同时支持“销售订单 → 出货计划 → 销售发货单”和“销售订单 → 销售发货单”两类追溯链路；
8.  展示关联装箱单；
9.  展示关联发运单；
10. 支持一张销售订单关联多条/多张下游业务单据；
11. 各业务单据编码支持点击；
12. 点击编码后在新浏览器页签打开对应源单据页面；
13. 追溯页面以只读汇总查询为主，不直接维护源单据。

### 7.3 本PRD补充内容

为保证功能可实施和可验收，本 PRD 在原始需求基础上补充：

- 查询条件和订单列表入口；
- 数量汇总与履约状态；
- 一对多单据关系；
- 数据权限和功能权限；
- 作废、撤销、红冲单据处理；
- 空数据、断链、接口超时等异常场景；
- 链接路由和新页签安全要求；
- 测试用例和实施确认清单。

## 8\. 开发规范

### 8.1 数据关联规范

- 使用内部唯一主键、来源单据主键或正式关联表建立销售订单与下游单据关系；
- 发货单关联查询必须兼容两种来源：`销售订单 → 出货计划 → 销售发货单`和`销售订单 → 销售发货单`；
- 对直接来源于销售订单的发货单，不得因出货计划主键为空而过滤或判定为断链；
- 发货单需保留来源类型，并能定位销售订单头主键和销售订单行主键；
- 不建议仅以展示单据编码进行关联，避免单据编码变更或跨组织重复导致错误；
- 关联关系至少能够定位销售订单头、销售订单行及对应下游单据明细；
- 多张下游单据合并时，应按业务明细主键去重，避免数量重复汇总；
- 数据断链时记录订单主键、单据类型、目标主键、检测时间和异常原因。

### 8.2 数量与单位规范

- 所有履约数量均需明确来源单据、明细行和单位；
- 主单位、辅助单位不得直接混合相加；
- 需要换算时，使用业务发生时的有效换算率并保留换算前数量；
- 作废、撤销、红冲、退货等单据的统计口径必须统一配置；
- 超计划、超发、超装箱、超发运应输出差异数量和异常标识；
- 前后端使用相同精度和舍入规则。

### 8.3 状态规范

- 源单据状态按源模块原值展示；
- 统一履约状态通过状态映射或规则计算，不修改源单据状态；
- 状态映射应支持实施配置，并记录配置变更；
- 撤销、关闭、红冲和删除必须分别处理，不得统一当作“已完成”；
- 履约状态刷新时机应与源单据提交、审核、出库、发运、签收等业务事件一致。

### 8.4 接口与性能规范

- 查询接口应支持按销售订单主键批量获取关联单据，避免逐行循环调用造成 N+1 查询；
- 各分区支持独立加载和失败重试；
- 大明细量采用服务端分页，不一次返回全部数据；
- 查询接口需返回总数、当前页、每页条数和稳定排序字段；
- 同一查询请求的重复调用应返回一致结果，不得产生业务写入；
- 追溯页面为只读查询，查询接口不得修改源单据；
- 性能目标由实施确认，建议常规订单追溯首屏在3秒内返回，单分区查询在2秒内返回。

### 8.5 权限与审计规范

- 前端菜单权限、按钮权限和服务端数据权限必须同时校验；
- 用户不得通过直接拼接 URL 绕过组织、客户、仓库或单据权限；
- 联系电话、地址、金额、司机信息等敏感数据按角色脱敏或隐藏；
- 记录追溯查询、源单据穿透和权限拒绝日志；
- 审计日志至少包括用户、时间、订单主键、目标单据类型、目标主键和访问结果。

### 8.6 路由与新页签安全规范

- 使用平台统一路由服务维护“单据类型 → 详情页路由”的映射；
- 禁止在业务组件中散落硬编码的环境域名；
- 跳转参数使用内部主键，不仅使用展示编码；
- 新页签打开链接时采用安全参数，避免目标页反向控制来源页；
- 目标页面必须再次执行登录状态和权限校验；
- 跨系统打开时应使用平台现有单点登录机制，不在 URL 中传递明文 Token；
- 目标页加载失败时展示明确错误，不自动关闭原追溯页面。

### 8.7 前端交互规范

- 单据编码链接样式在各分区保持一致；
- 表格空状态、加载状态、错误状态和重试交互保持统一；
- 页面返回时保留查询条件、页码、滚动位置和分区展开状态；
- 数量、金额、日期时间和状态展示遵循平台统一格式；
- 表格列较多时支持横向滚动、固定关键列或列配置；
- 不在追溯页提供源单据编辑操作，避免职责混淆。

### 8.8 明确不开发内容

本期不开发：

- 生产订单及生产过程追溯；
- 采购、供应商和来料追溯；
- 质量检验及质量证书追溯；
- 发票、应收和收款追溯；
- 物流地图、GPS实时轨迹和电子围栏；
- 客户外部查询链接或小程序；
- 在追溯页面修改、审核或删除源单据；
- 跨订单经营分析和 BI 报表。

### B. 风险与应对

| 风险  | 影响  | 建议措施 |
| --- | --- | --- |
| 历史单据未保存稳定来源关系 | 追溯链路断裂或关联错误 | 盘点历史数据，优先使用内部主键和来源关系表，必要时补建关系 |
| 各模块数量单位不一致 | 汇总数量失真 | 统一单位口径，按业务有效换算率换算并保留原数量 |
| 作废、红冲、退货口径不统一 | 履约进度与业务认知不一致 | 评审确认统计口径，建立可配置规则并形成验收样例 |
| 多张单据合并后重复统计 | 发货或发运数量偏大 | 按业务明细主键去重，并建立自动对账测试 |
| 源模块路由变化 | 单据编码链接失效 | 采用统一路由映射服务，避免页面硬编码 |
| 前端隐藏代替服务端鉴权 | 发生越权访问 | 所有源单据详情接口必须执行服务端功能和数据权限校验 |
| 大订单关联单据过多 | 页面加载慢或超时 | 首屏汇总、分区懒加载、服务端分页、索引和缓存 |
| 状态异步更新延迟 | 追溯状态短暂不一致 | 明确刷新机制、更新时间及异常重试策略 |
| 敏感数据展示过多 | 客户和物流信息泄露 | 按角色控制字段并执行脱敏和访问审计 |
