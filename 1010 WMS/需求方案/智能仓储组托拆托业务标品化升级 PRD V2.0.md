## 🔮 概述

### 1.1 产品定位

**智能仓储-组托拆托业务**：在 CJC-WMS 中将"托盘（Pallet）"升级为一等业务实体，覆盖组托 → 入库 → 移库 → 盘点 → 拆托 → 发货 → 退库 → 报损的全生命周期，解决「入库台账丢失托盘关系、整托发货不支持、部分拆分后剩余物料丢父托盘、销售按托合同与按件履约错位」四大核心问题。

### 1.2 用户故事

#### 一、生产作业端

**用户故事1**：作为车间 PDA 操作员，当产线下线产品需要组托时，我希望能在平板端扫码组托并选择物料/批次/数量，以托盘为单位完成入库前组装，否则入库单以物料为单位无法体现实物组合关系。

**用户故事2**：作为车间 PDA 操作员，当派工单完工时，我希望系统自动带出派工单的客户/完工日期，避免手工录入错误，否则托盘追溯链断裂。

**用户故事3**：作为车间 PDA 操作员，当一张合格证对应多个托盘时，我希望能一次扫码合并入库到多个托盘，以减少重复扫码，否则一个合格证 N 托盘要录 N 次。

**用户故事4**：作为车间 PDA 操作员，当需要在已组托的托盘上追加物料时，我希望扫码追加后托盘号不变、追溯关系保留，否则重打托盘码导致业务中断。

#### 二、仓储作业端

**用户故事5**：作为仓管员，当托盘入库时，我希望系统按托盘码自动关联入库单，避免手工台账维护，否则托盘关系容易丢失。

**用户故事6**：作为仓管员，当托盘需要移库时，我希望整托扫码调拨/移库而不是逐物料操作，否则效率低下且容易出错。

**用户故事7**：作为仓管员，当盘点时，我希望按托盘盘点并自动比对实物托盘 vs 系统托盘，差异定位到托盘级，否则按物料汇总无法定位实物。

**用户故事8**：作为仓管员，当托盘需要拆托部分发货时，我希望系统自动把剩余物料保留原托盘号，否则剩余物料"丢失"父托盘信息。

#### 三、销售发货端

**用户故事9**：作为销售内勤，当客户订单要求整托发货时，我希望系统支持一键扫码整托发货并自动生成出库单，否则按物料拣货效率低。

**用户故事10**：作为销售内勤，当一个发货单含多个托盘时，我希望出库单关联托盘清单用于运输配载，否则司机不知道装哪几个托盘。

**用户故事11**：作为销售内勤，当需要按托盘汇总销售配货时，我希望有报表统计每个托盘的客户/订单/物料/数量，否则配货统计散落。

#### 四、退货报损端

**用户故事12**：作为退货员，当客户拒收一托退库时，我希望系统能整托退库并保留父托盘号，否则退库后托盘关系失效。

**用户故事13**：作为仓管员，当托盘物理毁损时，我希望能在系统中登记报损并自动释放物料库存，否则坏托盘上的物料继续被系统占用。

#### 五、追溯合规端

**用户故事14**：作为审计人员，当需要核查托盘的全追溯链时，我希望从托盘码能反查到派工单/生产订单/客户/完工日期/作业人/时间，否则追责无据。

**用户故事15**：作为商务，当按托盘合同对账时，我希望每个托盘可关联到具体客户和派工单，否则无法精准计费。

#### 六、配置管理端

**用户故事16**：作为系统管理员，当不同客户需要不同托盘号生成规则时，我希望通过参数配置项适配，否则每个客户都要开发一套。

**用户故事17**：作为产品经理，当客户有特定组托/拆托业务规则时，我希望通过参数配置项定制（如"包材部按流延机台重置托盘号"），避免硬编码。

## 🧧 公共规则

| #   | 规则分类 | 规则描述 |
| --- | --- | --- |
| 1   | **托盘号生成** | `MMDD + 4位序号`（如 `0716-0123`）；按"组织+日"维度独立计数 |
| 2   | **托盘码格式** | 支持 QR/RFID/条码三模，扫码必须 1 秒内识别 |
| 3   | **追溯链必填** | 组托时必须填 `source_id`；完工时组托必须填 `customer_*` + `finished_date` |
| 4   | **追溯来源审计** | 所有追溯字段来源必须写入 `trace_audit` JSON（决策依据：追溯字段可来自不同源） |
| 5   | **删除规则** | 托盘/关联物料记录不允许物理删除，仅做逻辑删除（dr=1） |
| 6   | **审计日志** | 托盘状态变更必须进审计日志（含操作员/时间戳/终端类型/前后状态），日志不可删改 |
| 7   | **混托物料校验** | 混托场景下不同物料的批次号必须分别录入 |
| 8   | **拆分规则** | 拆托时剩余物料继承原托盘号 + 客户 + 完工日期 |
| 9   | **合并规则** | 合并源托盘状态变为"已合并"，目标托盘物料数量累加 |
| 10  | **退库规则** | 退库托盘状态变为"已退库"，物料回到库存待用区 |
| 11  | **报损规则** | 报损托盘状态变为"已报损"，物料从可用库存扣减 |
| 12  | **盘点锁** | 盘点中的托盘不允许移库/发货，但允许查看 |
| 13  | **三端适配** | PC 端管配置/报表/补录；PAD 端作业扫码；PHONE 端查状态/补打托盘码 |
| 14  | **跨期追溯** | 允许通过 `trace_audit.source_biz_id` 反向追溯到任意历史单据 |
| 15  | **客户特定规则** | 客户特定解析规则走参数配置（如"包材部按流延机台重置托盘号 #11558"），不进个性化分支 |
| 16  | **同生产订单限制** | 参数化控制是否允许同生产订单组托（新光 #12211 默认关闭，可开启） |
| 17  | **托盘备注** | 有托盘号必须有托盘备注（#12864 约束） |

## 💣 基础数据

### 1\. 系统参数设置（托盘业务规则配置）

**【适用范围版本】** V2026.10

**【功能描述】**  
配置托盘业务运行所需的全局规则参数，包括托盘号生成规则、客户特定解析规则、追溯链采集模式等。参数变更需记录操作日志。

**【功能说明】**

- **业务菜单**：仓库管理 → 托盘设置 → 托盘业务规则配置
- **业务按钮**：● 新增 ○ 编辑 ■ 删除 ● 查询
- **数据来源**：系统预置 + 管理员手工配置
- **数据去向**：各业务模块运行时引用

**【关键数据项】**

**主表：托盘业务规则参数（表名 wms_pallet_param）**

| 字段编码 | 字段名称 | 类型  | 长度  | 是否必填 | 默认值规则 | 联动逻辑 |
| --- | --- | --- | --- | --- | --- | --- |
| param_code | 参数编码 | nvarchar | 50  | 是   | 系统预置 | 程序引用此编码读取参数值 |
| param_name | 参数名称 | nvarchar | 100 | 是   | —   | 展示用名称 |
| param_value | 参数值 | nvarchar | 200 | 是   | —   | 当前生效值 |
| param_type | 参数类型 | integer | —   | 是   | —   | 1=枚举/2=布尔/3=文本/4=数字 |
| scope_org | 适用范围 | nvarchar | 50  | 否   | "ALL" | ALL/工厂编码/部门编码 |
| scope_customer | 适用客户 | nvarchar | 50  | 否   | —   | 客户编码，限定本客户生效 |
| description | 参数描述 | nvarchar | 500 | 否   | —   | 参数用途说明 |

**【处理流程及业务规则】**

- 【客户特定规则】：同一参数编码可按 `scope_customer` 区分客户，如 `pallet_no_reset_by_machine` 限定包材产销部
- 【优先级规则】：客户级 > 组织级 > 全局级
- 【修改规则】：修改时记录操作日志，参数生效时间可配置（立即/次日）

## 附录 B：状态枚举汇总

| 拆分类型 (split_type) | 1=部分拆分 / 2=整托拆零 |
| 发货类型 (ship_type) | 1=整托 / 2=部分发货 |
| 质检状态 (qc_status) | 0=未检 / 1=合格 / 2=不合格 / 3=待定 |
| 参数类型 (param_type) | 1=枚举 / 2=布尔 / 3=文本 / 4=数字 |
| 终端类型 (terminal_type) | PC / PAD / PHONE |
| 箱状态 (carton_status) | 0=开立 / 1=已装箱 / 2=已组托 / 3=已拆箱 / 4=已退库 / 5=已报损 |
| 拆箱类型 (unpack_type) | 1=部分拆箱 / 2=整箱拆零 |
